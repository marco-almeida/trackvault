Synopsis

trackvault is a cross-platform CLI that backs up your Spotify liked songs and every playlist (private ones included) into portable JSON files — and restores them into a new account.

Your library outlives the account it was built on. No web dashboard, no cloud: plain files on your disk, in a format you can inspect with cat.

 trackvault --help
trackvault --help TrackVault is a CLI tool to back up and restore Spotify library data. Usage: trackvault [command] Available Commands: login Authenticate with a provider (Spotify OAuth / PKCE) backup Back up liked songs and all playlists to a folder restore Recreate a backup in a new (or existing) account version Print version information

^Features
  • Spotify OAuth 2.0 / PKCE login Browser-based auth flow with a local 127.0.0.1 callback. Tokens are stored in your OS keyring — never in plaintext files.
  • Backs up liked songs + all playlists Includes private playlists. v1.4.0 enriched the data captured per playlist.
  • Restore into a new account Recreates playlists and re-adds every track, batched in groups of 100 with automatic retries on transient failures.
  • Portable backup format Plain, indented JSON in a timestamped folder. Diff it, grep it, commit it, copy it to a USB stick. Platform-agnostic.
  • Cross-platform Windows, macOS (Intel + Apple Silicon) and Linux (amd64, arm64, i386).
  • Zero config for the happy path One login, one backup, one restore. Defaults do the sensible thing.

^Setup walkthrough
6.1Create a Spotify Developer App

TrackVault requires your own Spotify Developer App. Create one at developer.spotify.com/dashboard — the app is only used to open the OAuth flow in your browser; no server is involved.

Your Spotify app is in dev mode until you submit it for review, so only accounts you add as app users/test users can log in. That's a Spotify limitation, not a TrackVault bug.
6.2Login
 step 1 — authenticate
trackvault login --provider spotify Your browser opens the Spotify consent screen. After you approve, the callback arrives on 127.0.0.1 and the token is stored in your OS keyring.

Using your own app credentials explicitly? Pass both (required together):

 optional — explicit client credentials
trackvault login --provider spotify --spotify-id <CLIENT_ID> --spotify-secret <CLIENT_SECRET>
6.3Backup
 step 2 — snapshot the library
trackvault backup --provider spotify -o . Progress bar shows per-playlist. Without -o, backups are written to the OS data directory for this user.

Each run creates a timestamped folder (YYYY-MM-DDTHH-MM-SSZ), so repeated backups never overwrite each other.

6.4Restore

Log in to the target account first (step 6.2 in the other account), then:

 step 3 — replay the backup
trackvault restore --provider spotify --source ./backups/2026-01-01T14-32-09Z Omit --source to restore the most recent backup automatically. Playlists are recreated, tracks re-added in batches of 100, with retries.
^Backup format

A backup is a folder: one metadata.json plus one .json file per playlist (named Name_ID.json). No database, no container — just JSON.

 tree -L 1 backups/2026-01-01T14-32-09Z
backups/2026-01-01T14-32-09Z/ ├── metadata.json # backup source, provider, timestamp, counts ├── Liked_Songs_spotify.json # your liked songs ├── Late_Night_Code_4aX1b.json # playlist name + ID └── On_Hold_9fQ2c.json # …one per playlist, private ones too
^Notes & disclaimer
  • Bring your own Developer App Login uses the Spotify OAuth flow; the app must be yours (see 6.1).
  • Dev-mode account restriction Until your Spotify app is submitted, only whitelisted accounts can authenticate — a Spotify-side limitation.
  • Backups are yours Copy the timestamped folder anywhere. Restoring needs only that folder and a login to the target account.
